## 4. V1：设计方向和代表页面

### 4.1 视觉方向

延续main的轻盈、温和风格：浅灰/暖白底、白色卡片、低饱和玫瑰色强调、细边框和克制阴影。使用现有中文系统字体、Lucide图标和Tailwind，不增加装饰性大图、复杂动画或外部字体依赖。

| 项目 | 初始设计建议 | 使用规则 |
| --- | --- | --- |
| 背景/卡片 | `#FAFAFA` / `#FFFFFF` | 区分工作区与内容块，避免整页粉色 |
| 品牌色 | main的 `#D4728A` | 用于图标、轻量强调；小字和主按钮需选更深色并验证对比度 |
| 主操作/浅底 | 候选 `#9F3F5B` / `#FDF5F7` | 统一主按钮、选中导航；最终以样板和可读性为准 |
| 文字/边框 | 深灰正文、次级灰、浅灰边框 | 不以过浅灰表示必要信息，禁用与只读明确区分 |
| 状态色 | 绿：已同步；蓝：处理中；琥珀：待处理；红：失败/危险 | 必须同时有文字或图标，不仅靠颜色 |
| 间距/形状 | 4/8/12/16/24/32px；圆角8–12px | 表单、卡片、弹层统一，优先信息密度与触摸可用性 |

正文建议14–16px；小字只用于辅助说明。普通文字对比度目标4.5:1，交互边界与大字目标3:1；手机主要点击区域建议至少44px。颜色是设计提案，不能只凭色值声称已通过可读性验证。

### 4.2 信息层级与布局

- 桌面：项目标题/身份入口在顶部；四业务页为主导航；页面标题、简短说明和主操作组成页内工具栏。导出、历史、回收站及链接管理进入明确标注的次级入口，避免顶栏同时摆满按钮。
- 同步状态保持可见但紧凑。正常状态简洁展示；本机保存失败、结果未知、冲突和撤权时显示完整解释及处理入口，不因美化隐藏风险。可折叠详情，但不自动关闭待处理提示。
- 手机：顶部保留项目和状态，四业务页使用紧凑导航；辅助操作进入可访问菜单。避免固定区域叠加挤空画布，处理安全区、软键盘、滚动及弹层关闭。
- 使用现有数据与命令接口。布局调整不得引入旧Supabase同步Hook、仅项目ID授权、失焦即共享提交，或丢失已有表单恢复入口。

样板范围为“统一外壳＋宾客页＋排座页”的桌面和手机布局；当前交付范围及缺口见§4.3。用户已确认视觉方向，未完成的冲突等状态在落地时补齐，不逐个按钮请求确认。

## 9. R2：正式冻结、迁移和切换

切换前给用户一份可审批的执行单：目标版本/环境、项目、窗口、备份位置、迁移批次、对账结果、操作责任和回退方案。确认的是具体批次，不是泛化授权。

1. 在两个旧来源后端停止相关项目写入，等待在途请求结束；验证已打开的旧标签页也不能写。只换导航或页面提示不算停写，不影响未迁朋友项目。
2. 处理尚未同步的本机草稿，重新完整导出并校验最终备份；旧表更新时间不可靠，不单凭updated_at做增量迁移。
3. 从最终冻结数据建立正式目标，执行与试迁相同的批次校验、完整回读和人工关键记录复核；任何不一致先停止开放。
4. 发布已审核的前端和网关版本，交付新协作/管理链接，验证入口与深链。旧ID链接不得绕过新凭证校验，也不得把管理秘密写在公开重定向表中。
5. 正式入口统一使用CloudBase，移除旧Supabase写入路径与不再需要的构建配置；在网络层验证没有双写。旧数据库及冻结备份保留，不立即删除。

当前仓库部署工作流仍要求过渡期Supabase配置。实施正式发布时须连同旧路由、依赖和实际托管保护一起核对，不能只改环境变量就宣称完成切换。

### 回退规则

- 新站尚无正式新写入：验证冻结备份和旧端可恢复后，可按执行单恢复旧入口/写权限。
- 新站已有正式新写入：先停写并导出新数据；优先修复新站。仅在新增变更已完整反向对账、旧格式无法表达的数据已妥善保存后，才允许退回旧站。
- 前端版本回退与数据库回退分开判定；回退代码必须兼容当前schema和数据代次。不直接切回旧库丢弃新修改。

## 10. R3：观察期与正式验收

建议至少7天，覆盖一次完整编辑、跨设备协作、导出及备份恢复抽查；这是建议观察长度，不是自动批准退役旧站。

- [ ] 脱敏观察保存失败、冲突、请求重试、备份/清理失败及资源用量；不记录名单正文、电话或链接凭证。
- [ ] 明确问题联系者和处理顺序，发现数据完整性风险先限制写入、保留证据和备份，再修复。
- [ ] 用户确认视觉、操作和数据均达到日常使用要求；剩余低优先级问题有清单和负责人。
- [ ] 确认旧系统退役、备份保留期限及未来维护安排；不自动删旧库。记录最终版本、域名、数据批次和验收结论。
