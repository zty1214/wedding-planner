# 最新草稿实现审查与修复

基线：`beeb902`（本轮开始时 HEAD），范围为当前未提交的命令草稿面板、笔记表单恢复及 Repository 衔接。依据融合方案 §9.4、A4；独立进行规范与方案两轴审查，主审复现并修复。没有修改云端权限、部署或真实数据。

## Standards

- **P2：初始化期间输入未落盘。** 编辑器原先在 IndexedDB 打开前已允许输入；保存失败后初始化完成又覆盖失败提示。修复为本机库及草稿列表初始化完成后才开放输入。初始化失败仍允许关闭空表单。
- 没有发现需据此进行结构重构的硬性规范问题。未找到独立 AGENTS/CONTRIBUTING 标准。

## Spec

- **P1：排队期间旧意图被绑定到新代次。** refresh 在等待网络时仍展示旧项目；原 dispatch 执行时才读取 epoch，导致旧笔记可能提交到恢复后的新项目。现调用时冻结 epoch，队列执行时再次比较；恢复的表单显式传入原 epoch。不匹配时拒绝进入 outbox，不改变云端。
- **P1：本机保存失败后关闭/恢复另一草稿会丢输入。** 原队列捕获异常后继续，关闭按钮直接卸载。现追踪最新输入是否已落盘；关闭与恢复均等待保存队列，失败保留当前编辑器及正文，允许另存或明确放弃。最新保存成功才解除保护；另拦截顶部链接与切换笔记按钮，防止绕过编辑器关闭入口。添加页面关闭提醒作为辅助，不承诺浏览器强制终止可恢复。

## 验证

- 原 89 项自动化通过；新增确定性 Repository 竞态测试，共 90 项通过。模拟 refresh 阻塞→提交旧意图→读回新代次，断言未发送、未落盘；同时验证已刷新后的旧表单显式 epoch 被拒绝。
- 浏览器使用 `scripts/fusion/review-note-drafts-ui.mjs` 的纯虚构内存故障适配器（无 CloudBase、凭证或真实项目）。运行后打开 `http://127.0.0.1:4181/__note_review`。
- 已实测：延迟初始化时字段禁用；模拟写入失败后关闭被阻止；恢复另一草稿、顶部导航和切换笔记均被阻止且正文不变；恢复存储→另存→关闭→重开→载入，完整正文找回。[故障截图](../validation/2026-10-05-note-draft-failure-review.png)。故障页面验证组件行为，IndexedDB 本身的事务/CAS 由既有 fake-indexeddb 测试覆盖，两者不混同。
- 类型检查、lint、生产构建、差异检查通过。构建仍提示大 chunk，本轮不视为性能验收。
