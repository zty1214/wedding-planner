## 工程正确性

1. **旧回执误确认不同草稿**：同一项目/代次/operationId 但不同 payload，在查询路径可直接取得旧回执，原 outbox 会删除未执行的草稿。回执新增完整命令的 requestDigest，客户端与冻结请求比较后才确认；不一致保留失败草稿。已有云端 StoredReceipt 从原 digest 补齐字段，不允许两个摘要不一致。通过真实 commandService + IndexedDB 模拟重开后的端到端回归。
2. **核心形状未校验导致假成功**：guests 为数组等错误结构可通过 truthy 检查；新宾客作为数组属性在序列化比较中丢失，仍产生成功回执。命令前后校验核心字典、字段、版本、日期、引用、座位唯一性和顺序。非法状态拒绝整个事务，不生成回执、活动或部分修改。

## 规格一致性

1. **提前开放有损住宿清空**：guest.assignRoom(null) 清除现有房间与晚次，但尚无原子恢复材料。当前阶段拒绝清空已有住宿；分房仍可用。回归确认整个项目事务内容不变。恢复材料实现后再开放该入口。
2. **缺少 shared 所属方**：类型、更新白名单与状态校验补齐 shared（双方），保留原分组文本。
3. **ID 字典不能保证显示顺序**：新增 guestOrder/tableOrder/roomOrder，校验为完整且不重复的 ID 集合；新增时维护，JSON 往返后数字 ID 也保持新增顺序。旧隔离探针状态没有顺序字段，不能推断原顺序，后续测试使用全新虚构项目；真实迁移尚未进行。
4. **抢座归类为普通失败**：SEAT_OCCUPIED 改为 conflict，保留草稿等待处理，补上队列回归。
