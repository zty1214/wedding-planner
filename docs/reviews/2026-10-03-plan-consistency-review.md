# 融合方案一致性复核（2026-10-03）

通读[主方案](../2026-10-02-planner-fusion-plan.md)、[术语表](../../CONTEXT.md)及四份 ADR，按产品、并发、权限、恢复、迁移和排期交叉核对。本记录是文档审查，不是运行时验证报告。

| 发现的具体缺口 | 已补充的执行规则 | 开发验证 |
| --- | --- | --- |
| 请求成功后页面被杀，重新打开可能生成新操作 ID | 冻结请求与发送状态先落盘，再联网；按原 ID 核验 | V3/V4 |
| 整项目恢复换代后响应丢失，旧代次回执可能无法查询 | 当前有效授权允许查询原代次回执；返回新代次，禁止旧代次写入 | V3/V5 |
| 创建成功但链接响应丢失，凭证摘要无法还原秘密 | 客户端安全生成并先保存两类秘密；相同创建请求幂等交付 | V2/V3 |
| 仅靠午夜定时任务无法保证前一天的版本 | 定时及跨日写入共用日结，先固定前日状态再写下一日 | V5/V6 |
| 整项目恢复后旧回收记录与新项目状态不匹配 | 记录绑定代次，旧代次只预览/导出，历史与活动不回滚 | V5/V7 |
| “有损操作”可能被实现为每次调整都记完整历史 | 明确删除/清除命令白名单，普通晚次及座位调整不生成回收记录 | V3/V7 |
| 已分房却改为需求待确认，造成待办列表互相矛盾 | 有房必须 needed；改为 pending 前先移出房间 | V8 |
| 每项目一份核心文档与隐藏代次恢复看似冲突 | 唯一生效代次，允许隐藏准备副本；核心/笔记同时受代次约束 | V5 |
| 出席来源映射、旧舞台空值、阈值冻结阶段及回退条件表述不一 | 标注 Planner 映射来源；舞台按核对基准；P1 定阈值、P4 复验；无反向转换时停写修复新站 | V1/V8/V9 |

可以从 P0/P1 开始分阶段开发。平台权限、日结与多文档恢复、90 天真实负载、手机体验和迁移恢复仍须按主方案留下实测证据。约一周是目标，不代表这些验收已通过；正式切换窗口、来源冲突及备份承诺在具体验证结果出现后确认。
