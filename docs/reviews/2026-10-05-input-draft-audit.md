# 主流程输入草稿检查

范围：Fusion 四个业务页面、历史页面；不把旧 Supabase 分支的表单实现当作 Fusion 实现。2026-10-05 按实际渲染分支检查。

| 输入 | 保存机制与本轮结论 |
| --- | --- |
| 新增/编辑宾客姓名、分组、电话 | FusionGuestForm 私有 IndexedDB 草稿；原 epoch/revision 保留，明确恢复后保存。 |
| 自定义分组名称 | 发现仅 React state；本轮改用 FusionFieldEditor，退出/刷新后可在添加类别入口恢复；保留 config revision，配置变化不静默重试。 |
| 桌名、房号、项目标题 | FusionFieldEditor 私有 IndexedDB 草稿；保留原记录版本；本轮将表单 ID 复用于保存请求，避免交接后换编号。 |
| 文本笔记标题、正文、分类 | FusionNotesEditor 独立草稿；旧 NotesPage 图片表单不在当前 Fusion 渲染分支。 |
| 手动版本名称 | 发现仅 React state；本轮改用 FusionFieldEditor。保存绑定开始编辑时的核心/笔记 revision，变化后要求重新核对；草稿恢复不自动创建版本。 |
| 晚次选择、出席、归属、房间、座位、桌子移动 | 选择或拖动结束即生成持久命令；未结束手势不是已保存命令。故障/触摸实测仍按 T07/T08 验收。 |
| 搜索、分组筛选、房型筛选、晚次筛选、历史日期、日历翻月 | 临时查看状态，不写业务数据；不作为需恢复的编辑草稿。 |

本轮跨存储检查发现：`version.save` 不改变业务 revision，若请求成功但表单清理未完成，原实现重新生成 operationId 会再建一个手动版本。字段保存现使用持久表单 ID 作为 operationId；重开、原请求回执核对回归确认只创建一个版本。载荷变化仍受既有请求摘要保护，不能用同编号覆盖旧请求。

新增自动化覆盖两个新增字段的重开、跨项目隔离、配置/核心/笔记 revision 变化、旧代次和版本名称长度，以及成功后表单未清理再保存的幂等性。尚待补充新增入口的浏览器刷新恢复、实际存储耗尽、操作系统强制结束、跨标签升级、移动端切后台。此记录不等于这些故障矩阵已经完成。
