## Spec：需求与权限、恢复语义

| 级别 | 原触发路径与需求 | 修复与验证 |
|---|---|---|
| P1 | 撤销凭证后 snapshot/pageStore 仍含远端数据并继续轮询；违反方案 9.4 权限失效处理 | 统一清空可展示快照与页面数据，停止后续轮询网络请求，保留持久草稿。包括业务发送、核心读取、历史和回收读取的拒绝。 |
| P1 | forbidden 草稿换有效凭证后仍无法恢复；违反重新授权后明确恢复要求 | 用户明确继续时先重新鉴权，只将拒绝状态恢复为结果待确认，保留原冻结命令与 operationId，先查回执后决定发送。已确认操作不会换 ID 重做。 |
| P2 | 每小时固定读取首 20 条，失败首批会永远挡住健康项目；违反分页批次要求 | 增加日任务持久扫描游标，失败也向后推进，扫到末尾再从头补偿。测试首批 20 个失败、后续健康项目仍处理，以及下一轮重试。 |
| P2 | 恢复预览只有数量/名称，无法辨认同人数的座位、晚次和布局变化 | 并列展示预览时当前与目标配置、舞台、桌坐标/容量/旋转、逐人座位、需求/房间/晚次；过期版本禁用恢复按钮，服务端继续拒绝过期恢复。 |

四项均已在本地代码修复。最高风险为撤权后仍展示远端内容；日任务游标尚未部署，不能把本地测试当作云端验收。

## 补充审查

- P2：网关已有 16 KiB 上限，但客户端只在云端被拒后才发现，超长中文笔记进入 failed 队列。共享 UTF-8 请求大小预检，在落盘和发送前明确拒绝，表单保留内容；服务端仍执行同一上限。6000 个汉字被预检拒绝，随后正常输入可成功保存。该值是既有探针限制，不是正式容量验收结论。
- P2：项目标题失去焦点时不等待本地保存结果就清空编辑状态。现等待保存结果，失败保留输入；异步完成不清除其间的新输入。
