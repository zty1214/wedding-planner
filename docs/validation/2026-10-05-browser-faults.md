# 主流程本机浏览器故障验收

入口：`node scripts/fusion/review-main-flow-ui.mjs`，打开 `http://127.0.0.1:4182/__main_review`。仅监听本机地址，使用专用虚构项目 `browser-main-flow-fixture`，不连接 CloudBase。真实浏览器 IndexedDB、Repository、字段编辑器、草稿面板保持实际实现；传输层用本地虚构服务替身，服务状态与回执保存在该测试源的 localStorage 以支持刷新。

这是浏览器组件与持久存储故障注入证据，不是实际断网、真实磁盘写满、CloudBase 撤权或云端故障证据。重新载入会重置初始化/离线/拒绝访问等故障开关，保留虚构服务数据与本机草稿；累计写入从上一次值继续，重复验收应比较增量。

## 已执行

1. **初始化保护**：完成初始化前标题、桌名、房号全部禁用。
2. **本机写入异常**：点击“下一次表单落盘失败”后填写桌名“不能丢失的桌名”。字段保留输入并显示失败，点击“切换页面”被阻止；点击组件的“重试本机保存”后确认落盘。[截图](2026-10-05-field-quota-guard.png)。注入的是 vault.save 抛错，未真的耗尽系统存储。
3. **断网保存→重开**：断网开关开启后保存桌名，进入 unknown、1 项待确认，服务写入 0。刷新后为 resume_required、原共享桌名、仍 0 次写入；没有自动提交。核对参考快照显示版本 0 的原桌名/房号，[截图](2026-10-05-browser-cache-baseline.png)。明确恢复后为 synced、待确认 0、写入 1。
4. **执行成功但响应丢失**：开启丢响应，保存房号“丢响应房号 003”，出现 unknown、1 项待确认、累计写入 2。刷新仍为待恢复；明确恢复后原回执被确认，累计写入保持 2，队列清空。[截图](2026-10-05-browser-lost-response.png)。
5. **暂停草稿时撤权**：离线保存标题“撤权后仍保留的草稿”，重开后未提交；先成功载入参考版本，再模拟撤权并刷新。状态为 forbidden，共享安排及已载入参考版本隐藏，草稿标题完整保留，写入仍为 2。[截图](2026-10-05-browser-revoked-drafts.png)。刷新重置替身权限开关后仍需明确恢复，之后写入变为 3。
6. **列表自动更新**：发现恢复同步后草稿面板停留旧列表，已修复为订阅 pending/status 变化；放弃确认期间冻结已审阅批次，不自动替换用户正在确认的内容。修复后第 5 项同步结束，未点“刷新列表”即显示 0 项，[截图](2026-10-05-browser-draft-list-refresh.png)。
7. **提示修复**：无共享快照时不再误提示“可能来自恢复前”；改为“当前访问权限尚未确认……暂不能核对它与当前安排的关系”。

`npm run check` 通过：143 项自动化、150 人/90 天场景、类型检查、lint、构建。尚需真实云端和独立客户端故障验证、表单→命令跨库交接强制崩溃、手机后台切换及跨标签升级；此入口本身不是已接入 CI 的自动浏览器测试。
