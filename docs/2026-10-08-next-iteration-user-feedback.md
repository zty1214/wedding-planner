关键关联：Planner迁移中，有房者映射stayNeed=needed，无房者映射pending，以免猜测住宿需求；新建宾客也默认pending。现在过滤器将这些人全部排除，造成“只能搜到以前分过房的人”的体验。出席、住宿需求、房间和晚次是不同事实，不应为让搜索可用而批量修改真实名单。

舞台补充：已有mainStagePos时中心不再随stageW变化，但舞台宽度仍用min(stageW×0.35,260)，窄画布会变宽窄；囍字始终依赖stageW/stageH。不得只固定默认x，遗漏已保存舞台、缩放和平移后的尺寸或水印行为。

## 二、建议实施顺序与完成标准

### 第一阶段：U4搜索范围与U3住宿操作闭环

1. 宾客选择器默认搜索全名单，提供“全部 / 已确认出席 / 需要住宿 / 未分房”的明确筛选；姓名、分组、电话匹配保持一致。显示出席、住宿需求、当前房间和个人晚次，不用出席状态推断住宿需求。
   空结果必须区分“全名单无匹配”和“当前筛选无匹配”，提供清除筛选入口；不能像当前页面一样一律建议去宾客名单添加，否则已存在但被隐藏的人可能被重复录入。
2. 已在本房的人标为已安排；已有其他房间的人标为移入，操作前说明将更换原房间。住宿待确认/原不需要者均可被找到，明确执行安排住宿时再设为needed；不把全名单先批量改成needed，不默认确认出席。不出席者仍保留可搜索及状态提醒，不发明服务端没有的出席硬门槛。
3. 页头添加房间：创建请求成功持久保存在本机后，立即打开该新房的宾客与房间住宿晚次弹窗，自动聚焦搜索；不要求先得到云端确认，离线时明确显示待同步；新房不被当前房型筛选隐藏。取消弹窗保留已建空房并清楚提示，不自动删除。实际实现需取得本次创建房间id，不能猜测“数组最后一个”，以免并发协作错房。
4. 弹窗为房间统一选择项目内的住宿晚次，选入的多位宾客共享这一房间安排。例如夫妻A住两晚、B只住第二晚，系统仍记录AB房间使用两晚，不采集内部实际入住差异。新房晚次默认待定，提供主动应用当前筛选晚次或全部晚次入口；已有房间编辑保留房间原晚次，保存前显示完整日期及跨年提示。
5. 选人和房间晚次一次确认作为整批保存；任一宾客或房间发生冲突则整批不写入，表单保留供核对。原子命令覆盖房间晚次、宾客房间关联和住宿需求，沿用请求冻结、回执、草稿及冲突机制。不能继续以逐人setStayDates串联模拟整批成功。移入已有房间显示目标房间晚次，不为一个人改动悄悄覆盖全房晚次。
6. 每晚用房按房间安排晚次计数，同房多人只计一间；容量提示基于房间安排人数，不宣称是真实每晚入住人数。仅已有宾客安排且明确住宿晚次的房间计入报房；空房不计，不引入酒店预留房功能。独立安排分别建立唯一房号，房内同住者晚次统一。零项目日期允许创建空房/晚次待定并提供设置日期入口，不伪造日期。

验收：全名单、已确认及其他筛选可切换；pending未分房、needed未分房、其他房间、本房间、同名不同人、前导零电话均有虚构用例。134/150人及至少30房时，新房按钮一次操作进入弹窗，无需到页尾；确认后的宾客关联/房间晚次刷新和另一个浏览器回读一致。网络失败、日期配置被删除、宾客被他人改动、重复点击不能产生假成功或重复房间；取消不改变宾客。390px与真机软键盘/滚动/触摸分别验收。

### 第二阶段：U1画布坐标稳定

1. 世界中的舞台采用稳定坐标和尺寸，视口只承担显示宽高、缩放与平移。缺省舞台是可重复的世界坐标缺省值，不随每次选桌重新计算；不为一次点选隐式写入云端布局，不任意重排迁移桌子。
2. 桌详情栏优先覆盖或占据稳定保留区域，避免选中/取消时整幅安排跳动；确需改变视口尺寸时，明确保持原视图的世界锚点。
3. 囍字为装饰，建议放在独立屏幕装饰层，保持画布视图中的稳定锚点；禁止用变化后的屏幕尺寸重新生成内容层世界坐标。导出单独固定构图，不把详情栏是否打开带入导出结果。
4. 拖舞台、滚轮缩放、定位适配、移动端详情抽屉和导出共用清楚的坐标规则；已有mainStagePos必须原样保留。

验收：在固定浏览器窗口内，连续打开/关闭不同桌详情，舞台/水印不突跳、桌位不变、项目配置不产生写入。覆盖mainStagePos=null与已有坐标、20%/80%/100%/放大、平移后点选、窄屏抽屉、窗口缩放；PNG在相同固定构图下不因选桌状态改变布局。使用真实Chromium/Konva几何及触摸验证，不能只测纯函数。

### 第三阶段：U2房间顺序与默认命名

1. 提供可切换的排序入口，例如房型分组（组内房号自然排序）、房号、创建顺序；不只固定一种排序。首次默认房型分组，排序作为本机个人偏好记忆，不影响其他协作者。首期使用“房型分组 / 房号 / 原始顺序”；缺少可靠时间的原始顺序不能称作创建时间。展示当前排序说明；含数字的1/2/10不能按字符串排成1/10/2。非数字房号保留可理解的中文排序。房间号在同一项目中唯一，新建/改名需校验；既有重名先提示并保留原始数据，不自动重命名，完成明确处置前用稳定id区分。
2. 排序先作为显示层行为，不改旧房id、关联或来源provenance，不整批重写roomOrder。浏览器/筛选/刷新/第二客户端必须一致；新建后即使排序位置在中间，仍直接进入该房弹窗。
3. 默认房间号在整个项目中选择未使用编号，房型作为独立字段展示；避免用全部房间总数+1生成“大床房15”；保留用户手工命名及001前导零，不自动重命名已有房间。手工拖排序未在本轮反馈要求中，不扩展为新领域命令。
4. 同批修正桌子的默认命名：`pageStore.ts:50`同样使用数量+1，第1/2/3桌删除第2桌后再新增会生成重复的第3桌（实际PageStore虚构调用已确认）。只为自动名称选未占用编号，保留已有和手工名称，不新增全局唯一名称约束。住宿Excel当前也另行按字符串排序，房卡自然排序落地时同步导出展示顺序，避免页面1/2/10而表格1/10/2。

验收：混合房型、1/2/10/001/中文/重名、改名后、删除重建、筛选后及两客户端显示一致。原始房号和宾客关联完整保留。房号展示排序不改变个人住宿晚次或覆盖率统计；具体日期筛选同时限定房卡及入住人为该晚实际有安排的对象。

全名单默认搜索已经用户确认；房间排序已改为可切换，默认与记忆方式已由Q7确认，不把之前的固定排序建议当作最终决定。后续实施应记录最终采用的规则；不借展示改进重写真实宾客状态、旧房号或迁移事实。业务实施、部署和真实数据变更分别按用户授权推进。
